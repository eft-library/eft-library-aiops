# 보안 및 운영 배포 — Phase 1~2

## 현재 보호 범위

- Codex에는 준비된 샘플이나 Phase 2가 생성한 정제 스냅샷만 전달한다. `analyze` 자체는 마스킹하지 않는다. Collector의 규칙 기반 마스킹은 알려지지 않은 비밀을 모두 제거한다고 보장하지 않으므로 최초 운영 배치를 검토한다.
- 분석 임시 디렉터리는 실행 후 제거한다. 실행 메타데이터 파일 권한은 0644, 새 데이터 디렉터리는 0755이다. 운영 접근 편의를 위해 같은 서버의 다른 계정에도 읽기를 허용하는 정책이며 인증 저장소·환경 파일에는 적용하지 않는다.
- 읽기 전용 샌드박스, 승인 금지, 사용자 config·규칙 제외, 프로젝트 문서 제외, 웹 검색 비활성화를 적용한다. 샌드박스가 작동하지 않으면 권한 우회로 재실행하지 않는다.
- 프롬프트는 도구 실행·수정 금지 및 로그 속 지시 무시를 명시한다. 다만 프롬프트만으로 공격 저항을 보장하지 않는다. Phase 3에서 추가 공격 입력 검증을 수행한다.
- 기존 인증 저장소는 CLI가 관리한다. 프로그램은 인증 파일 내용을 읽거나 출력하지 않는다. 자식 프로세스 환경변수는 허용 목록만 전달한다.
- timeout·예외·키보드 중단 시 프로세스 그룹을 SIGKILL로 종료하고 회수한다. 정상 종료 후 남은 그룹 내 자식도 정리한다. 즉시 종료를 사용하므로 정상 종료 유예는 없다.
- 원문 stdout/stderr는 메모리에서 파싱 후 폐기한다. 보고서 stdout은 사용자 측 저장/전송 시 민감정보 검토가 필요하다. Codex 런타임 자체 캐시·인증 갱신·진단은 AIOps 메타데이터와 별개다.

## 운영 배포 시 확인할 사항

1. 실행 계정에는 필요한 로그 읽기 권한과 Codex 인증이 있어야 한다. 높은 권한으로 실행할 때는 파일 읽기 범위가 넓으므로 수집 경로를 YAML에 명시하고, Codex에는 원본 경로 탐색 대신 스냅샷만 제공한다. 향후 최소 권한 계정으로 전환할 때는 그 계정의 인증도 준비한다. 인증 파일을 Git에 넣거나 공유하지 않는다.
2. 모든 CLI·스케줄 실행이 동일한 전용 `AIOPS_DATA_DIR`를 사용하도록 설정한다. 이 디렉터리는 운영 로그·서비스 설정·DB 데이터 경로와 분리하고 다른 계정의 쓰기 권한을 허용하지 않는다.
3. read-only는 쓰기 제한이며 작업 디렉터리만 읽을 수 있다는 보장이 아니다. 전용 계정의 파일 권한으로 비밀·운영 설정·DB 데이터 디렉터리 읽기를 막는다. 필요하면 전용 컨테이너/OS 격리를 추가한다. 단순 `cwd` 제한을 읽기 격리로 간주하지 않는다.
4. 네트워크는 Codex 통신에 필요하다. 로그를 외부 분석 서비스로 전송하므로 Phase 2 마스킹과 전송 대상 검토가 필요하다. 수집과 AI 호출은 별도 명령이며 `collect` 자체는 외부 AI로 전송하지 않는다.
5. `uv sync --locked`, `aiops doctor`, 소량 샘플 분석 순서로 확인한다. 검증한 Python·CLI 버전과 자원 사용량을 기록하고 메모리/CPU 제한은 운영 서비스 관리자 설정에서 별도 적용한다. 현재 Python 코드가 메모리 제한을 강제하지는 않는다.
6. 메타데이터는 기본 자동 삭제하지 않는다. 운영 보존 기간을 결정해 AIOps 데이터만 대상으로 정리한다. 원본 서비스 로그는 수정·삭제하지 않는다.

Phase 2의 저장·복구·경로 제한·보관 정책은 [COLLECTION.md](COLLECTION.md)를 따른다. 심볼릭 링크를 건너뛰고 일반 파일만 읽지만 root 권한 자체를 축소하는 보안 경계는 아니다. 현재 로컬 테스트는 Linux 권한 격리·운영 부하·운영 로그·DB·Airflow 검증을 대신하지 않는다. 이후 배포 절차는 PHASE3.md를 따른다.

## 심화 조사 조회 범위

일일 심화 조사는 설정된 로그의 제한된 tail, 시스템·컨테이너 지표, 설정된 AIOps DB의 읽기 전용 통계만 조회한다. HTTP 요청에서 임의 명령·경로·SQL·접속값을 받지 않으며 모델 응답은 저장·표시용으로만 사용한다. 기존 Codex read-only 실행 경계는 유지하고 과거 보고서·조회 입력·출력을 다시 마스킹한다. 마스킹의 한계와 실제 조회 범위는 [INVESTIGATION.md](INVESTIGATION.md)에 명시한다.

심화 조사 계획은 최대 5개 도구 요청으로 제한하며 전체 계획을 검증한 뒤 고정 조회 함수에만 전달한다. 모델이 제안한 셸·SQL·경로·URL은 실행 입력으로 받지 않는다. 추가 과거 로그는 원본 일일 보고서의 배치 manifest 범위만 읽고 수집 체크포인트를 변경하지 않는다. 프로세스 요약은 알려진 프로그램의 개수·RSS만 조회하며 인수·환경·실행 경로를 읽지 않는다. 계획·관측·최종 인계 모두 저장 전 마스킹한다.
