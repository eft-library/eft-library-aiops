# 조회 전용 운영 웹

문서의 `<...>` 값과 `/example/` 경로는 예시입니다. 복사해서 실행하기 전에 실제 배포 환경의 값으로 바꾸세요.

조회 전용 웹은 운영 결과를 조회한다. 수집·분석 접수·재시도·취소·설정 변경 기능은 제공하지 않는다. 실행 스케줄과 DAG는 별도 Airflow 프로젝트에서 관리한다.

```text
브라우저 → 웹 서버의 GET 조회 프록시 → AIOps API → PostgreSQL
```

브라우저에 API 키를 전달하지 않는다. 웹 서버만 기존 AIOPS_API_TOKEN을 읽고 API에 전달한다. 웹의 `/read/`는 status, reports, reports/{id}, collections, jobs GET 요청만 허용한다. 외부 경로·임의 URL·POST 요청은 전달하지 않는다. 다른 호스트로의 API redirect도 따르지 않는다. 웹은 고정 계정 로그인이 필수이며 로그인하지 않은 사용자는 보고서와 서비스 로그를 조회할 수 없다.

## 시작 및 종료

프로젝트 루트에서 기존 .env를 유지하고 실행한다.

```sh
./restart.sh
```

브라우저 주소는 `http://<WEB_HOST>:<WEB_PORT>`이다. API·웹 각각 독립적인 프로세스로 실행한다. restart-web.sh는 의존성 반영 후 웹 프로세스만 교체하고 `/health`에서 준비 상태를 확인한다. API/DB 실제 연결 실패는 화면에서 표시한다. restart.sh는 의존성을 한 번 반영한 뒤 API → 웹 순서로 함께 재시작한다. API 준비 확인이 실패하면 웹 재시작은 진행하지 않는다. 웹 시작이 실패해도 이미 시작한 API는 유지된다. 전체 상태 확인은 `./restart.sh status`, 전체 종료는 `./restart.sh stop`이며 웹 → API 순서로 종료한다. 개별 관리는 `./scripts/restart-api.sh`와 `./scripts/restart-web.sh`를 사용한다.

```sh
./scripts/restart-web.sh status
./scripts/restart-web.sh stop
```

웹 상태/PID는 AIOPS_DATA_DIR/run/web.pid, 로그는 log_history/web-YYYY-MM-DD.log에 저장한다. 날짜는 Asia/Seoul 기준이며 자정을 넘겨 실행해도 다음 기록부터 새 파일에 쓴다. API 로그와 별개이며 시스템 재부팅 후 자동 시작은 제공하지 않는다.

선택 설정:

```dotenv
AIOPS_WEB_API_URL=http://<API_HOST>:<API_PORT>
AIOPS_WEB_HOST=<WEB_BIND_HOST>
AIOPS_WEB_PORT=<WEB_PORT>
```

기존 AIOPS_API_TOKEN을 사용한다. DB 변경이나 npm 빌드는 필요 없다. HTML/CSS/JavaScript는 Python 패키지 안에 포함되므로 `uv sync --locked`만으로 반영된다. CLI 직접 실행은 `uv run aiops --env-file .env web`이다.

## 화면

- 대시보드: 최근 완료된 보고서 위험도·요약, 최근 일일 보고서의 관측 이벤트와 수집 슬롯, 전체 대기 작업 수, 최근 일일 보고서 기반 7일 추이, 최근 보고서.
- 분석 보고서: 일일·주간·월간 유형, 위험도, 분석 상태, 기간 시작일 범위, 이전 수정본 포함 여부, 페이지 조회.
- 보고서 상세: 관측 사항, 원인 가설, 확인 권고, 근거 이벤트/하위 보고서, 분석 한계, 관측 범위, 버전과 모델 정보. 일일 보고서는 장애 분석·성능 분석 구역도 표시하며 문제 관측/판단 근거 부족을 구분한다. 이전 형식의 보고서는 구역이 없음을 안내한다.
- 수집 현황: 최신 등록 배치의 서비스별 coverage·경고, 배치 이력. 소스별 최신 배치 결과이며 서비스의 실시간 정상 여부를 뜻하지 않는다.
- 작업 현황: 상태별 작업 목록, 시도 횟수, 접수·완료 시각, 오류. 실행·취소 버튼은 없다.

모든 화면의 시각은 한국 시간이다. 분석 완료와 수집 범위 충족은 별도로 표시한다. 0건과 데이터 없음은 구분하고, 보고서가 없는 날짜를 0건으로 그래프에 집계하지 않는다. 같은 기간의 기본 목록은 최신 수정본만 보여주며 이전 수정본은 필터로 포함한다. 날짜 필터는 보고서 기간 시작일 기준이다. 데이터는 페이지 진입과 새로고침 버튼에서 조회한다.

보고서는 저장된 분석 시점의 결과다. 수집 후 새 보고서를 준비하지 않았다면 이전 보고서가 최신 수집 배치까지 반영했다는 의미는 아니다. 분석 입력에서 생략된 근거는 원문이 없음을 표시한다. 로컬 샘플·가짜 분석 결과를 운영 화면에 자동 삽입하지 않는다.

## 조회 API

API 인증 방식은 기존 X-AIOps-Key와 같다. 목록 page는 1부터, page_size는 기본 12·최대 100이다. 응답은 items/total/page/page_size 형태다.

- GET /v1/reports: type=daily|weekly|monthly, status, severity, start/end=YYYY-MM-DD, history=true, page/page_size.
- GET /v1/reports/{id}: 기존 result 필드를 유지하면서 period/kind/revision/data_quality/totals/evidence/lineage를 추가한다.
- GET /v1/collections: page/page_size.
- GET /v1/jobs: status, page/page_size.

새 조회는 DB read-only 세션으로 실행하며 파일 복구·분석 요청·보고서 재생성·DB 마이그레이션을 수행하지 않는다. 빈 목록·API 연결 실패·인증 실패·없는 보고서는 화면에서 구분해 표시한다.

## 사이트 로고와 가독성

프로젝트 루트 favicon.ico를 브라우저 아이콘과 사이트 로고로 함께 사용한다. 루트 파일을 우선 제공하고, 설치 패키지만 있는 환경에서는 패키지 안의 동일한 아이콘을 사용한다. 원본 ICO를 변형하지 않으며 새 파일로 바꾸면 다음 조회부터 원본을 제공한다.

본문·표의 글자 크기와 대비를 높이고, 수집 범위 불완전 안내를 대시보드 위쪽에 표시한다. 보고서 상세의 구역 탐색으로 종합 요약·장애·성능·분석 한계로 이동할 수 있다. 새로고침·탐색만 제공하며 실행 기능은 추가하지 않는다.

## 일일 심화 조사 표시

일일 보고서 상세의 심화 조사 구역에 별도 접수된 조사의 상태·관측 시각·원인 확인 순서·대응 조건·위험·복구 확인·되돌리기·재발 시 확보 자료를 표시한다. 과거 증거와 현재 관측은 구분하며 명령을 실행하지 않는다. 조사 미접수·실패여도 일일 보고서는 유지한다. [조사 계약](INVESTIGATION.md)을 참고한다.

## 수집 상태 표현

파일·기록·탐색 한도에 따른 분할 처리는 “이어서 수집 예정”, 미완성 줄 보류는 “다음 확인 대기”로 표시한다. 실제 읽기 실패와 확인이 필요한 항목은 따로 표시하며 API의 원래 status·coverage_complete 값이나 판정 기준을 변경하지 않는다. 다음 실행에서 처리 완료됐음을 이 표시만으로 보장하지 않는다. 일일 화면은 수집 실행 구간, 서비스별 처리 참고 사항, 시각·수준·인코딩 등 데이터 품질을 구분한다. 이전 AI 보고서 본문의 누락 표현은 재작성하지 않는다.

## 심화 조사 운영자 인계

새 조사 결과에는 “지금 할 일”에서 대응 시점·우선 행동 1~3개·결과별 판단·점검 완료 기준을 먼저 표시한다. 자동 추가 조회 목록에는 실제 도구·대상 별칭·관측 시각·조회 상태를 표시하며, 상세 대응에는 기대 효과·사전 확인·예상 부작용·검증·되돌리기를 제공한다. 상세 조사와 수동 확인 명령은 접어두고, 이전 형식은 그대로 조회할 수 있다. 조치 실행 기능은 제공하지 않는다.

보고서 상세 맨 아래의 “전체 근거 모아보기”는 기존 개별 근거와 심화 조사 관측을 하나의 텍스트 영역으로 모아 제공한다. 펼친 뒤 영역별로 끊기지 않고 드래그·복사할 수 있다. 제공된 보고서 응답에 포함된 근거만 표시하며 전체 원본 로그를 추가 조회하지 않는다.

응답시간 서비스 DB 연동을 설정하면 일일 보고서 상세에 “정기 서비스 응답 점검” 표를 표시한다. 서비스별 관측 구간·유효 표본·측정 실패·평균·최대·p95·p99·전날 평균을 밀리초로 제공하며, 사용자 전체 요청의 통계와 구분한다.

## 고정 계정 로그인과 서비스 로그

운영 반영 전에 `.env`에 `AIOPS_WEB_USERNAME`, `AIOPS_WEB_PASSWORD`, `AIOPS_WEB_SESSION_SECRET`을 지정한다. 세션 키는 최소 32자의 임의 비밀값이다. 다음 명령으로 생성할 수 있다.

```sh
uv run python -c 'import secrets; print(secrets.token_urlsafe(48))'
```

비밀번호와 키는 Git에 기록하지 않는다. 웹 계정은 DB 접속 계정과 별도 설정이며 기본 계정·익명 조회 모드는 없다. 기존 DB 초기화 없이 `./restart.sh`로 API·웹을 반영한다. 로그인 값이 없으면 웹은 시작하지 않는다. 개별 웹 재시작은 기존 프로세스를 종료하기 전에 설정을 검증한다. Airflow의 API 키 호출은 변경하지 않는다. 브라우저에서 HTTPS를 사용하는 배포에서는 `AIOPS_WEB_COOKIE_SECURE=true`를 설정한다.

로그인은 JSON POST로 전달하며 서명된 임의 세션 쿠키만 브라우저에 저장한다. HttpOnly·SameSite=Strict, 절대 만료 8시간을 사용한다. 세션은 웹 프로세스 메모리에 최대 32개 보관하며 로그아웃하면 해당 세션을 폐기한다. 재시작하면 기존 세션은 모두 만료된다. 로그인 실패는 IP 기준 분당 최대 10회로 제한한다. API 키·로그인 비밀번호는 HTML이나 브라우저 저장소에 포함하지 않는다.

서비스 로그는 활성 파일 소스별 최근 파일을 선택해 본다. 자동 선택은 제한된 탐색 범위에서 가장 최근 파일을 따르고, 개별 파일을 선택하면 해당 경로의 교체·축소를 감지한다. 디렉터리는 최근 수정 순으로 우선 탐색하되 1,024개 항목·0.5초, 파일 목록은 최대 50개다. 전체 파일 탐색을 보장하지 않는다. 압축 파일·심볼릭 링크를 제외하고, 열 때도 각 경로 구성요소에서 링크를 따라가지 않으며 일반 파일만 읽는다.

처음 최근 64KiB 범위에서 완성된 줄만 읽고 서명 커서로 이어 읽는다. 한 응답은 최대 300줄, 한 줄은 마스킹 후 최대 약 4KB, 화면 버퍼는 최대 1,000줄이다. 미완성 줄은 다음 조회에서 확인하고 너무 큰 줄은 내용을 노출하지 않고 건너뛴다. 제한·파일 교체로 이전 기록 일부가 생략될 수 있으며 전체 보관 로그나 감사 로그를 대체하지 않는다. 원본 파일·수집 체크포인트는 변경하지 않는다.

검색·수준 필터는 현재 화면 버퍼에만 적용한다. 자동 스크롤을 끄거나 일시정지할 수 있다. 일시정지는 스트림을 닫고 다시 연결하면 기존 커서에서 제한된 범위를 읽는다. 다른 페이지 이동·로그아웃 시 스트림을 닫는다.

브라우저는 인증된 `GET /logs/stream` SSE로 수신한다. 웹 서버가 API의 인증 필수 `GET /v1/logs/tail`을 약 1초 간격으로 조회하며 API 키는 서버에만 둔다. 스트림은 60초마다 재연결하고 동시에 최대 8개다. 매 전송 전 세션을 확인해 로그아웃·만료 뒤에는 데이터를 보내지 않는다. `GET /v1/logs/services`, `GET /v1/logs/files`는 설정 별칭·불투명 파일 ID만 제공하며 임의 경로·셸 명령은 받지 않는다. Codex·DB 조회는 호출하지 않는다. 운영 프록시는 SSE 응답 버퍼링을 끄고 스트림을 허용해야 한다.

마스킹은 규칙 기반이므로 운영자만 접근하도록 관리한다. 로그가 오래됐거나 나오지 않으면 실제 로그 저장 경로와 수집 설정을 확인한다.
