# 운영 수집 결과를 반영한 보완

2026-10-28에 제공된 배치의 로컬 복사본을 검토했다. 원본 서버에는 접속하지 않았고 Codex를 호출하거나 운영 서비스를 변경하지 않았다. `prd_logs/`는 Git 제외 상태를 유지했으며 실제 운영 메시지를 테스트 fixture로 복사하지 않았다.

## 확인된 원인

- Next.js와 FastAPI가 전역 물리적 줄 수 20,000개를 소진해 이후 소스가 run_limit으로 밀렸다. 정규화 이벤트 수와 물리적 줄 수는 다르므로 이벤트 14,458개에서도 한도에 도달할 수 있다.
- 제공된 Next.js 이벤트 5,583개 전부와 FastAPI 이벤트 중 1,245개에 파싱된 시각이 없었다. 검토한 형식은 Next.js stdout·스택 출력과 Uvicorn WebSocket/연결 로그 등 실제로 시각이 없는 형태였다. 현재 데이터에서 이를 일일 날짜로 복원할 수는 없다.
- FastAPI 접근 로그의 말미 응답 시간과 Next.js 예외 클래스·닫는 중괄호가 충분히 처리되지 않았다.

## 수정

- 전역 줄 수·파일 수·시간을 소스별로 배분하고 파일별 줄 수도 배분. 서비스 시작 순서 순환과 새 파일/미수집 파일의 재방문.
- 정확한 단일 파일 경로 직접 확인, 이어가는 디렉터리 탐색, 제한된 추적 파일 순환. 탐색 상태는 배치·체크포인트와 원자적으로 확정.
- 탐색 개수/시간 경고 분리, 소스 시간의 일부를 실제 파일 읽기에 예약.
- FastAPI 응답 시간, Next.js 오류/스택 꼬리, 명시적 시간대·Redis·Nginx 형식 보완. 시각 미기록과 형식 미인식을 구분하고 URL 속 날짜를 이벤트 시각으로 채택하지 않음.
- 과거 배치·체크포인트는 삭제하거나 소급 수정하지 않음. 신규 수집부터 적용.

## 검증

- 제공된 마스킹 이벤트 메시지를 로컬에서 재정규화했다. Next.js는 스택 꼬리를 결합해 3,965개 이벤트가 되었으며 모두 timestamp_absent로 남았다. 날짜를 만들어 넣지 않았다.
- FastAPI는 8,875개 이벤트 중 1,245개를 시각 없음으로 유지하고, 응답 시간 6,282건을 인식했다. 표본에서 시각 형식 미인식은 0건이었다.
- `uv run pytest -q`: **133 passed, 1 skipped**. 기존 회귀 테스트와 추가 17개 테스트 통과. 실제 Codex opt-in 테스트는 실행하지 않음.
- 작은 전체 줄 수/파일 수에서도 서비스별 진행 확인, 한도보다 많은 서비스의 순환, 같은 디렉터리 내 파일 배분, 작은 탐색 한도에서 파일/재귀 디렉터리 재발견, 저장 실패 시 탐색 상태 롤백을 검증했다.

운영 원본의 새로운 수집에서 서비스별 진행과 경고를 다시 확인해야 한다. 원문 시각이 없는 로그를 정확히 일일 배정하는 문제는 로그 출력 측 타임스탬프 추가가 필요하다. 현재 Collector는 이를 임의로 보완하지 않는다.


## 후속 전체 수집 검증

후속 제공 배치에서 Next.js·FastAPI뿐 아니라 PostgreSQL·Redis·Kafka·Consumer·Airflow·Health·NPM·RustFS까지 읽기가 진행됨을 확인했다. Kafka 상세는 2개 파일을 확인했으나 신규 payload 0바이트였으며 탐색 항목 한도 경고가 남았다. 따라서 모든 로그의 수집 완료로 선언하지 않는다.

Next.js 이벤트 9개 모두 시각이 파싱됐다. FastAPI의 시각 없는 이벤트 346개는 이번 표본에서 이전 로그가 포함된 상태이며, 파일에 남아 있는 과거 레코드에 새로운 시각을 만들어 넣지 않는다. 수집 배치에는 7월부터 10월까지 과거 보관 로그가 포함되어 있었고 일일 집계는 각각의 이벤트 날짜로 배정한다.

추가 미인식의 대부분은 PostgreSQL LOG 수준과 NPM 추가 접근 로그 형식이었다. LOG는 INFO로 정규화하고 원래 수준을 metadata.native_level에 보존했다. NPM 단일 상태 코드 및 upstream '-'도 집계하며, 접근 로그 수준은 반환 상태로 판단한다. Airflow health의 명시적 성공·실패 표시도 인식한다.

같은 제공 이벤트의 로컬 재정규화 기준 parse_failed는 **2,727개에서 409개**로 감소했다. PostgreSQL 1,987개, Redis 2,000개, Kafka 436개, Consumer 2,400개, Airflow 2,400개, Health 10개, RustFS 386개는 시각·수준 인식에 성공했다. 남은 항목은 주로 과거 FastAPI의 시각 없는 기록, NPM 비표준/부분 기록, 수준 없는 Next.js 출력이었다. 이는 원본 운영 파일 전체가 아닌 제공된 표본의 결과다.

검사한 URL query token/access_token/api_key 값 중 미마스킹 후보는 0개였으며 마스킹된 값의 출현은 269회였다. 모든 종류의 민감정보를 완전히 검사했다는 의미는 아니다.

회귀 테스트 **141 passed, 1 skipped**, 패키지 빌드 통과. 실제 운영 파일·기존 저장 배치를 수정하지 않았으며 신규 Collector 실행부터 파서 변경이 적용된다.
